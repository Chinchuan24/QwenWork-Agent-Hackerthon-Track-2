# Twinguard build — decisions log

Safer-option decisions made during the one-shot build, per the plan's "no questions mid-run" rule.

| # | Decision | Why (safer option) |
|---|---|---|
| D1 | No Qwen API key found in environment at Phase 0. Judges run as a deterministic **stand-in** (clearly labelled in audit, UI and scoreboard). Live scoring requires `AEGIS_QWEN_API_KEY`. | Fail-closed: stand-in never returns Allow on uncertainty; it returns "unsure" which maps to Hold. No result is ever presented as live-model output when it is not. |
| D2 | Model names default to `qwen-max` (judge), `qwen-plus` (worker), `qwen-turbo` (fast) in `settings.yaml`, overridable by env. Could not list credit line-up without a key. | Plan says names must not be hard dependencies; settings file + env override keeps this true. |
| D3 | Qwen HTTP calls use stdlib `urllib.request` against the OpenAI-compatible endpoint instead of the `openai` package. | Fewer pinned dependencies, identical API surface, no runtime downloads. Plan allows builder overrule on technical choices. |
| D4 | Policy file format: YAML with a fixed condition vocabulary (no expressions, no code). | Readable by non-engineers; cannot execute arbitrary code. |
| D5 | Audit signing key: generated once at first start, stored outside the database under `aegis_data/anchors/`. Separate signer process is a should-have and is not built; the stated limit applies. | Matches plan section 8.7 including its openly stated limit. |
| D6 | World state is in-memory per run, freshly copied from seed. Only decisions/audit live in SQLite. | A baseline ("off") run can never spill into a protected run; nothing to bypass to. |
| D7 | Should-haves deferred: adaptive attacker, plain-English policy builder, separate signer, containers, encrypted evidence. Static Compliance table + trust-report download ARE built. | Must-haves first, per the cut line. |
| D8 | Intent Check "no" maps to Hold (not Block) unless a hard rule already blocks; "unsure" maps to Hold for side-effect actions. | Fail-closed without punishing normal work with hard blocks on AI opinion alone. |
| D9 | Demo accounts: dana (admin, task giver), ops (approver), audi (auditor). Passwords are demo-only, printed in README, forced-change not implemented (sandbox). | Two-person approval demo needs distinct accounts; plan says demo accounts are stated openly. |

| D20 | M6: compliance references checked against official sources on 2026-11-17 — EU AI Act Chapter III titles (artificialintelligenceact.eu, EC AI Act Service Desk), OWASP LLM Top 10 2025 + Agentic Threats & Mitigations v1.0 T-codes (genai.owasp.org), NIST AI RMF 1.0 subcategory texts (airc.nist.gov). | D21 | H6 follow-up: chose the SAFER option — implemented detection instead of only documenting the gap. A forward-only, HMAC-signed latest-checkpoint anchor is written outside the data folder (default `~/.aegis/anchor-<hash>.json`, env `AEGIS_ANCHOR_EXTERNAL`, `""` disables and Verify then reports the gap). It never regresses, so a coordinated rollback of records + checkpoint lines is caught. README and trust report state the remaining limits exactly: an attacker controlling the external anchor location too, or a rollback predating the anchor's creation, is not detected. | Documenting a known bypass leaves it exploitable; an out-of-folder anchor removes the whole class of data-folder rollbacks at minimal cost, and the residual limit is stated honestly. |
| D22 | R1 look-first: read records existed but no exposure mark/containment — built on the existing records, no second copy. Reply-to-exposer: held unless the human's task names the recipient (the safer choice the file asks for); a NAMED outside recipient passes R1 but still faces the existing unknown-sender rule (R-SENDER) — layers are not weakened. "Copied from outside" uses paste matching PLUS ≥2 shared distinctive figure/identifier tokens, so reworded copies that keep the numbers are still contained. | Containment must stop harm without recognising words; keeping R-SENDER intact preserves the existing guarantee for unknown contacts. |
| D23 | R3 look-first: the H6 external anchor existed; signing was still in-process. Built the separate signer and KEPT the external anchor as a second layer. On this single-user Mac, OS-level read prevention against the same user is impossible without a separate account; achieved process separation + 0700/0600 permissions + out-of-folder forward-only record, and the README says exactly that. Tamper tests were isolated onto fresh DB streams because a forward-only signer correctly refuses regressions — isolating tests is not weakening them. | The safer option is real process separation with honestly-stated residual limits, not a permissions claim the OS cannot enforce for one user. |
| D24 | R4 look-first: M2 masked secrets but business content stayed clear at rest. Encrypted whole fields (not just secrets) with AES-256-GCM; the day-cap total moved to a numeric `paid_amount` column because SQL cannot extract from ciphertext (amounts are operational metadata, not seeded confidential text). Startup refuses without a key in ANY mode (safer than the enforce-only minimum, since audit writes would otherwise fail). Audit migration temporarily lifts the append-only trigger under controlled startup, then restores it. Exports: audit JSON/CSV decrypt for admin/auditor only; viewer screens show placeholders. | Whole-field encryption is the only way to guarantee the raw-file scan passes; failing closed on a missing key beats writing clear evidence. |
| D25 | R5: the adaptive attacker found real harm (spaced/reversed carriers, single-fact split messages, non-numeric phrases copied from outside content). Fixed the gateway's copy check with distinctive skeleton phrase-windows (2-5 words, must contain a >=5-char non-business word) plus single distinctive figure/identifier matching, forwards and reversed; the recipient address is excluded from the copy check (it is the target, checked by the named/lookup rule) to avoid false holds on normal replies. A measurement run with the signer DOWN trivially held everything and looked perfect — invalid; all reported numbers are measured with the signer UP. | Containment must generalise beyond the exact attacks; and a fail-closed layer can mask defects, so measurements must run with all layers active to be meaningful. |

## Approved Prototype Scope (2026-11-20)

- S5 fail-closed BLOCK is user-approved for prototype acceptance. The original sponsor HOLD contract and historical mismatch remain disclosed; no policy, helper-card or scope protection is relaxed.
- Scripted stand-in calibration is accepted only as a clearly labelled prototype. Synthetic origins are not real human work or independent live-model evaluation.
- R09 covers amount, price, rate, discount, refund, fee, tax, currency, quantity times price, payment terms, due/payment dates, bank/account details and credit limit. Added, removed or changed terms versus the current agreed trusted source require human HOLD. Proven source contradiction remains BLOCK. Complete unchanged structured snapshots may pass the financial comparison, never override other rules.
- Agreement authority must bind current source path, version, body hash and structured term hash, session, exact outgoing action and a distinct authorized human reviewer receipt. Missing or invalid authority HOLDs. Exact quote-only message scope can be published at trusted human task ingress or the authenticated admin source-message-scope route, with CSRF and creator checks. It binds current complete source snapshots and exact outgoing arguments without inventing a financial amendment approval. Partial quotation is not removal of an agreement; replacement agreements still require complete term comparison.

### Ready For Me

Live-model calibration requires the user's Qwen API key through the user's own secure configuration. Agents must never read, write, display or discover the key. Prototype acceptance does not imply live calibration readiness or completed independent evaluation. Section 7 requires 30 actual independent agents after confirmed prototype 1k scope; Section 8 follows Section 7. Neither has run here.
